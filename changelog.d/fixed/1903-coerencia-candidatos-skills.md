- **Candidatos de skills coerentes entre CLI e gateway (#1903):** o endpoint `GET /api/learning/logs/candidates` passou a ler os dois escopos do registro pelo mesmo helper da CLI (`registry::scan_candidates_scoped`), então o candidato que `garra skills mine` grava em `~/.garra/skills/_candidates` deixa de sumir do Web Console. Cada item informa o escopo onde foi encontrado e os escopos seguem isolados.
- A raiz global de skills passou a resolver `HOME` com fallback para `USERPROFILE` (Windows) numa função compartilhada (`registry::home_dir`/`user_home_dir`); o gateway não cai mais num `/tmp` inline quando a variável falta.
- Contagens honestas: `garra skills mine` e `garra skills candidates` separam arquivos encontrados, sessoes/candidatos válidos e arquivos ignorados, com aviso acionável no stderr nomeando o arquivo ilegível. `mine` também distingue padrões detectados de arquivos novos (idempotência) e sai com `EX_NOINPUT` (66) quando nenhum arquivo tem sessão válida.
- `garra skills list` mostra quando o escopo declarado no frontmatter diverge do diretório onde a skill está instalada.
- `garra skills mine` passa a morrer em silêncio por SIGPIPE (`garra skills mine | head -1`) em vez de entrar em pânico com stdout fechado: o minerador termina todas as escritas antes de imprimir.
