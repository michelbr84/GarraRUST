- A CLI ganha `garra skills mine` / `garra skills candidates` / `garra skills list`: o pipeline de skills (minerador de padrões de sessão + registro) deixa de ser alcançável só pelo gateway. Sem servidor no ar agora dá para minerar `~/.garra/sessions`, ver os `mined-*.md` pendentes em `~/.garra/skills/_candidates` e listar as skills instaladas nos escopos global e de projeto.
- `mine` grava candidatos de forma idempotente (arquivo existente não é reescrito) e usa o mesmo limiar mínimo de 2 sessões do minerador; `--sessions-dir` aponta um dump alternativo, `--threshold` sobe a exigência, e `--json` serve a automação. Diretório de sessões ausente sai com `EX_NOINPUT` (66) em vez de silêncio, e `--threshold 0` com `EX_USAGE` (2).
- Os diretórios vêm de `registry::global_skills_dir()` — a mesma fonte que os handlers de learning do gateway usam —, então a CLI e o servidor nunca relatam árvores diferentes. Nenhum caminho novo é inventado.
